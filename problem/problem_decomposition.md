# B 题炼钢厂钢包周转与排产优化问题拆解

2026-11-26 · 校赛模拟赛 · 与 [选题决定](../stages/01_topic_selection/topic_decision.md) 配套

## 1. 总问题与边界

给定炉次生产计划，在钢包从转炉经过指定精炼工序进入连铸、再空包回程的过程中，决定何时派哪台行车去哪里，怎样行驶和避让，保证生产任务按要求衔接，并减少等待和运行时间。题面在同一调度目标下给出三个场景。三个场景共用一份炉次事件链、任务表、生产约束与共轨冲突模型。 [B 题原文](<../docs/校赛题目/B题：炼钢厂钢包周转与排产优化问题/B题：炼钢厂钢包周转与排产优化问题.docx>)

| 范围 | 题设事实与基本解释 |
| --- | --- |
| 工艺流 | 3 座转炉、2 台 LF、2 台 RH、3 台连铸机。每炉走仅 LF、仅 RH、LF→RH 或 RH→LF。初始方案按计划路线、设备和同浇次顺序建模 |
| 运载资源 | 主要研究 EF 跨共轨行车。1#、2# 各 150 吨，3#、4#、5# 各 450 吨。按钢水与钢包总吊重和站点可达性分配行车，共轨运行不可跨越 |
| 空包回程 | 连铸后空包吊离、翻渣、过渡平车、热修、返回转炉区域。使用 1#–3# 渡车接收，空包也可由 450 吨行车运送。题设钢包数量足够，行车、渡车和接收位仍可能被占用 |
| 时间衔接 | 确保具备起吊条件且按要求到位。同浇次连铸保持顺序和连续供钢。过早到位可能占用接收位并增加降温时间，过晚有断浇风险 |
| 范围边界 | EF 的载运、空驶、等待和待避进入同一轨迹。其他跨和热修等工序按确认的设备能力或可获得的时窗接入。不可达、不可移或不兼容的任务应显式标记 |

## 2. 三问共用的数据与模型接口

### 2.1 从计划与日志生成炉次任务

**计划提供需求和目标时间。** 出钢计划表用于读取炉次、转炉、精炼路径、连铸机、连连浇号、浇次序号和计划时刻。已核对原表中「连铸开始/结束」为空，应使用「浇铸开始/结束」。将值为 −2 的占位单独登记。按精炼路径明确「精炼 N 时间」的含义。缺乏时窗的工步使用已说明的估计口径，记录哪些窗口由题设固定。

**历史日志提供观测。** 工序时间信息、转炉、LF、RH、连铸分表用于重建出钢结束、吹氩后钢车到位、精炼进出位、吊起、座包、开浇、停浇、空包吊离、翻渣及渡车交接。以熔炼号连接，并用设备、路线和时间核对重复记录。出钢记号、钢包号和临时罐号用于消歧。时间戳统一转换到含日期的秒级时间轴，时长统一成秒。空值区分工序未经过和真实缺失。倒序、重复表头或多表冲突按事件语义择源，保留原表行与异常说明。

**任务表是共同接口。** 每段运输至少含炉次、浇次、载重状态、起讫站、总吊重、前序、物理可吊时刻、到位窗口、可用行车和参数来源。重包任务连接当炉必要工序，空包任务接续浇铸、翻渣和渡车。空车调位由行车上个任务终点和下个任务起点派生，初始位置也进入状态。计划与实际分别存储，用真实记录估计时长和偏差分布。 [A 方数据核对](../stages/01_topic_selection/A/A_math_modeling_analysis.md) · [B 方实现与数据意见](../stages/01_topic_selection/B/B_implementation_analysis.md) · [短验证输入及原表行号](../stages/01_topic_selection/validation/b_crane_dispatch/problem/case.json)

### 2.2 共同决策变量、硬约束与目标口径

对任务 $h$，设 $r_h$ 为物理可吊时刻，$[l_h,d_h]$ 为允许放下区间，$m_h$ 为总吊重，$K_h$ 为满足载重和站点可达性的行车集合。决策包括分配 $y_{hk}$、起吊 $s_h$、放下 $a_h$、空驶与等待的位置和时间、各行车轨迹 $x_k(t)$。状态包括钢包所在工序、设备与接受位占用、渡车是否就绪，以及行车位置和载荷。场景 2、3 还需保留速度、档位和故障状态。

$$
\sum_{k\in K_h}y_{hk}=1,\qquad s_h\ge r_h,\qquad l_h\le a_h\le d_h,\qquad
x_{k+1}(t)-x_k(t)\ge D_{k,k+1}.
$$

行车按各共轨区段的初始位置排序，$D_{k,k+1}$ 为相邻车的最小净距。公式需与路段端点、站点和局部避让规则一起使用。净距检查覆盖**有载、空驶、等待、待避和停在轨道上的故障行车**。同一行车同时只承运一项任务。给下一项任务预留空驶与必要的装卸时间。设备、接收位、翻渣位和渡车按相应占用及容量约束检查。

炉次工序按前序执行，保持计划锁定的设备顺序与同浇次的炉次次序，换中包的间隔另行解释。计划开浇为 $C_h$ 时，可把 $d_h=C_h-b_h$ 作为暂定的最晚座包口径，其中 $b_h$ 为座包后至开浇的必要提前量。最早座包由接受位和允许提前量约束。吹氩、钢车和精炼离位决定 $r_h$。历史实际起吊可作为缺少直接观测时的保守代理。存在明确的工艺最长等待或温降限值时，将其转为相应时窗，缺失的限值按假设区间分析。

**目标的工作定义。** 先满足硬安全、工序顺序和约定的计划时窗。在可行排程中，优先压缩需要等待的任务时间，再比较行车空驶与有载运行时间。分别报告上游等车 $s_h-r_h$、到位后等待开工、行车待命，以及空驶和有载运行。对照策略使用相同口径。无法满足计划时报告超窗、断浇风险或不可行下界，安全约束保持为硬约束。

## 3. 场景 1 · 精确工序时间与匀速行车

**题目要求。** 给定精确工序时间，行车匀速，操作切换不计时间。输出一份可执行的行车分配和时间表，让计划所需任务及时到位并避免共轨冲突。

| 步骤 | 要解决的问题 | 交付及验收 |
| --- | --- | --- |
| S1.1 生成确定性窗口 | 将计划与已确认的工艺时间转为每段运输的可吊时刻、接收窗口与占用。区分固定计划时刻和模型估计时刻 | 任务清单、时间来源、候选行车、设备与浇次前序。抽样对回原表 |
| S1.2 构造可行排程 | 同时选择行车、出发、空走、等待和待避。优先完成余量紧的重包，安排后续空包回程。行程按距离和给定速度确定 | 每段任务的分配、起落时刻及五车时空轨迹。检查吊重、可达性、渡车、工序连续性和所有时段的最小净距 |
| S1.3 指标与不可行诊断 | 在同一模型下比较规则基线和改进方案。先做理论最早到位检查，再分析资源或算法造成的寻找失败 | 逐工序等待、行车运行时间、座包余量、可行或失败原因。分段线性轨迹在共同断点检查相邻净距 |

以短验证中的真实浇次作为回归案例，先用可行插入或预约，再增加包含不同路线和并发压力的窗口。设 $p_{hk}$ 为行车 $k$ 完成任务的必要时间。当 $r_h+\min_{k\in K_h}p_{hk}>d_h$ 时，在该输入下即使忽略空驶和共轨冲突也赶不上。串行构造或启发式搜索无候选时，继续区分搜索局限与物理不可行。短窗精确优化可用于标定规则的性能差距，历史全量数据服务于参数估计和样本选择。 [短验证结果](../stages/01_topic_selection/validation/VALIDATION_SUMMARY.md)

## 4. 场景 2 · 随机工序时间与行车动力学

**题目要求。** 计划工序时间是均值并有随机波动。考虑行车启动、停止、不同速度档位，以及特定位置降速和换位避让。给出可执行调度策略及不同实现条件下的可靠程度。

| 步骤 | 要解决的问题 | 交付及验收 |
| --- | --- | --- |
| S2.1 刻画随机时刻与历时 | 比较历史计划与实际，估计开工偏移及处理历时。保留同炉次或同时间块的依赖，区分系统偏差与随机波动。生成的历时非负并满足已知前序 | 样本来源、剔除口径、分布或重采样规则、实际中心与题设均值之间的处理说明。用留出时间窗检查合理性 |
| S2.2 生成可实现的运动轨迹 | 在场景 1 的几何和安全模型中加入分段限速、换挡、加减速与特殊区域的空间占用。保持区段边界速度连续 | 带时间戳的位置、速度、档位和避让记录，检查启停、区段限速和共轨净距。对相对速度可能过零的区间检查内部最小净距 |
| S2.3 调度策略与比较 | 按更新的就绪时刻和剩余余量调度，比较场景 1 原策略与加入缓冲或调整优先级的策略 | 用同一批扰动样本比较按时到位率、计划完成率、断浇次数或频率、等待中位数与高分位数、运行时间。仅使用决策时已知的状态 |

先用少量轨道段与预计算运动模板，待核实实际档位和限速后再扩大。站对端点耗时可用来约束总服务时间。缺少距离、速度档位和实际待避位置时，以参数区间呈现敏感性，并注明结果依赖的假设。

## 5. 场景 3 · 故障与动态重调度

**题目要求。** 各工序可能发生故障。出钢、吹氩或钢车等延迟影响钢包可吊时刻，行车间干扰也影响实际可行窗口。给出能尽量保住生产计划次序的重调度方法，以及资源受限时的处理边界。

| 步骤 | 要解决的问题 | 交付及验收 |
| --- | --- | --- |
| S3.1 识别受影响任务与当前状态 | 记录故障机位、发生时刻、已知恢复窗口、受影响任务与行车当前轨迹。区分未开始任务、已执行动作和无法中断动作 | 故障前后状态与影响任务集。以实际事件发生时可获得的信息为准 |
| S3.2 局部滚动修复 | 保留已执行或不可中断的动作，更新可吊时刻、设备占用和轨道状态。优先重排受影响任务，保持已知路线和同浇次次序 | 一份可执行的新任务表、轨迹与原计划差异。校验净距、载荷、前序及连铸交接。仅在有明确依据时考虑更换设备或改路线 |
| S3.3 比较策略与恢复边界 | 用原计划或固定规则作对照，至少覆盖就绪延迟和工序短时不可用。逐步增大扰动识别何时耗尽交接缓冲 | 恢复到连续可执行计划的时间、延期或未完成任务、断浇风险、受影响任务数、等待和重排幅度。若保序与硬时窗无法同时满足，指出不可行窗口和原因 |

故障率与修复时间缺少直接观测时，使用明确的注入情景。停机行车若占据轨道，必须保留其位置和阻挡作用。对于超过物理缓冲的故障，报告原计划的失效位置和滚动策略还能恢复的服务范围。

## 6. 前置核实、交接与最终交付

| 优先级 | 马上核实的事项 | 对后续的约束 |
| --- | --- | --- |
| 1 | 把短验证首炉的 LF1 可吊时刻和 CC3 最晚座包时刻对到工艺事件 | 决定硬时间窗。若精确值缺失，保留可辩护的上、下界并报告首炉可行域 |
| 1 | 核对 EF 共轨行车顺序、关键站点、渡车与待避位以及可达行车 | 决定线路与净距模型。仅有无比例尺示意时，用条件布局和参数区间表达结果 |
| 2 | 核对 LF 站号、精炼时间字段、同浇次的接受位规则与连铸换包口径 | 固定任务转换和连续性验收。不同资料冲突的字段保留原始值与取舍 |
| 2 | 收集可用的档位、加速度、限速区和故障记录，并核对可改派的条件 | 影响场景 2、3 的物理精度和外推范围。缺失时按可核验的区间和故障情景处理 |

**推进顺序。** 先锁定事件、单位和任务接口，再完成场景 1 的端到端轨迹与对照。场景 2、3 共用场景 1 的约束检查器，可在接口冻结后并行推进。成员 A 主导模型定义及代码整合，成员 B 主导数据核对、参与调度实现，并负责对照实验和图表，成员 C 独立校验数学约束、数据和论文结论。

**交付清单。** 三个场景各给出可追溯的数据输入、方案与可行性检查、对应的对照实验和解释。用逐任务表、共轨时空图、炉次甘特图、等待及到位风险分布、故障前后差异支撑正文。题面规定 Word 或 PDF 的解决方案不超过 25 页，含一页摘要、目录、完整解答和参考文献，AI 使用报告与附录按题面规定另计。
