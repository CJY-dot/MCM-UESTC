# 场景三故障动态调度

沿用 A 的炉次事件图、行车与资源预约，以及场景二的运动模板。故障触发后先锁定实际执行历史，按实际状态生成安全续行边界。先局部修复，必要时滚动重优化，优先维持已锁定的生产顺序和同浇次供钢。B 已用就绪延迟注入检查首项运输结束后的前缀，这里进一步定义处理中断、带载制动及占轨。 [题面场景三](../../../problem/problem_decomposition.md#5-场景-3--故障与动态重调度) · [A 模型 §7](../A/A_model_proposal.md) · [B 参数摘要 §3](../B/B_parameter_summary.md)

## 1. 事件与状态

以秒表示时刻，轨道坐标用米或声明的归一化单位。对每条事件记录故障源、受影响资源、真实发生时刻 $t_f$、策略收到事件的时刻 $t_o$、已经确认的停复机状态，以及发布给策略的恢复区间与发布时间。模拟可取 $t_o=t_f$，另测响应滞后。晚收到信息时，按真实日志继承到当前时刻 $\tau\ge t_o$。物理模型在 $t_f$ 起演化，策略在 $t_o$ 才获知。无可验证恢复上界时，已承诺动作仅使用当前可确认能力。将不同可能恢复时刻作为后续条件分支。

| 故障或扰动 | 事件图与资源更新 | 可行处置 |
| --- | --- | --- |
| 转炉出钢推迟、吹氩或钢车晚到 | 更新尚未完成的出钢、吹氩、钢车就位事件及其占用。用前序完成和必要交接时长更新该炉及下游 $r_h$。钢车仍占用至实际离位。 | 推迟未开始取吊，调配其他已就绪炉次的未承诺任务。可在授权范围内按共同预测预调位。 |
| LF/RH 等工序停机 | 禁止停用期间开始或完成要求该设备能力的新作业。已在位钢包及接收位持续占用。对在制工序记录已完成量、剩余量及完整性。允许续作、必须重做、需工艺处置三类用配置或公告选择；恢复后仍计必要检查、出位与工艺时间。 | 原路线内延后收发和工序。只有已核设备兼容、工艺允许、接收及移动可行时才改设备，锁定的路线和顺序继续落实。 |
| 连铸接收位或转台停用 | 关闭相关容量，保留在位钢包、当前供钢进度和可用缓冲。更新实际供钢截止或剩余时间。 | 先做清障和可执行的重包衔接。若连续供钢失效，记录首个中断及受影响浇次，按授权定义重启条件。 |
| 行车故障或临时阻塞 | 从在途状态延伸制动和停驻轨迹；故障车暂停接新任务，带载包和在途任务随车。其他车的空驶、载运、待避预约一起检查。 | 在确认可达的分区内重派未开始任务。待恢复许可确认后续行或按经验证流程交接。 |
| 同时或相继发生组合故障 | 同刻更新所有公告和现场占用后，按依赖图重算就绪和轨道冲突闭包。相继事件从最新已执行状态再算一次，资源不可用区间取并集；串行工艺按实际前序传播。 | 联合修复。等待占用或路径冲突可能把影响传播至原本不相关的浇次，必须重新校验共用资源。 |

对每次滚动时刻 $\tau$，保存可追溯的状态快照：

- **行车。** 记录五车的轨段、$x_k(\tau)$、带符号速度 $v_k(\tau)$、档位/方向、工作模式、钢包和任务 ID、吊重、起落进度、正在执行的运动段、制动/停驻参数与恢复状态。
- **生产。** 保存各炉已完成事件、在制工序及剩余服务、真实在位及就绪状态。对连铸保存正供钢炉次、实际消耗或可供钢至何时、接收位、转台、后续炉序及锁定交接。
- **钢包与资源。** 钢包唯一持有者为某工位、某车、渡车或外部交接资源。记录重量及其来源、温度或允许持包时限（若已确认）、占用起点和确知释放条件。钢包充足的题设仍保留单个钢包、车位和接收位的占用守恒。
- **计划与信息。** 冻结历史实际前缀、已发出的近期指令、不可中断动作和已发布的恢复信息。未执行的未来预约保存原计划 ID、锁定级别和可重排范围。仿真内部的故障结束真值在公布前留在事件引擎。

## 2. 行车触发、制动、停驻与恢复

以下是运动和调度仿真接口。制动上限、反应时滞、故障位置和带载约束需由现场参数或明示情景给定。

1. **触发。** 在 $t_f$ 取实际状态 $(x_f,v_f)$。故障立即撤销该车接受新任务的资格。起吊、落包或持包时，以已确认的实体持有者和动作阶段继续跟踪。故障前的轨迹及取放事件保留。
2. **反应与制动。** 简化情景设反应时滞 $\delta\ge0$，其间按 $v_f$ 继续，随后用大小 $b>0$ 的常减速度沿运动反向制动。令 $w=|v_f|$，$\epsilon=\operatorname{sgn}(v_f)$，$x_b=x_f+v_f\delta$。制动开始后 $u$ 秒有

   $$
   x=x_b+v_fu-\epsilon bu^2/2,\qquad v=v_f-\epsilon bu,\quad 0\le u\le w/b .
   $$

   停车时刻为 $t_s=t_f+\delta+w/b$，停位为 $x_s=x_b+\epsilon w^2/(2b)$。若开始时已静止，直接按已确认停驻状态处理。其他反应轨迹由实际记录或状态转移给出。$x,v$ 在衔接处连续，制动受轨段、限速、载荷和设备能力约束。若反应/制动仅有区间，可同时检验多个实际可达包络，作保守承诺时用相关最不利占用范围。检查其他车辆从各自实际速度能否减速，禁止用位置跳变或瞬时停车消去冲突。
3. **停驻。** 在 $[t_s,t_r)$ 固定 $x=x_s,v=0$，持续占用轨道包络，并与两侧活动车保持净距。带载时钢包和已起吊任务跟随该车，目的工位的预约可在授权范围内调整，实物占用按交接事件更新。调度器须检查 $t_s$ 前的扫掠区和 $t_s$ 后的固定障碍。其余车辆从同一实际切点续行，原预约只有通过新回放才可执行。
4. **恢复。** $t_r$ 指确认设备可运行、有工艺与安全许可、载荷和站位状态核对完成的时刻。维修预计结束可作为预测时点，实际接单须等待确认。恢复时从实测位置和速度开始；仍带载则先履行已绑定任务的剩余动作，或执行经授权且经容量、载荷和轨迹复核的交接。重加入前检查邻车间距、目标可达、速度连续、所需工位与后续完全可停条件。

若故障后的反应或制动扫掠与轨界或邻车冲突，报告发生时刻、冲突区及所用参数，按现场应急流程等待指令。当前调度模型可计算状态下的可行性，无法撤回已经执行的物理动作。为了减少此类风险，可在预约基线增加制动余量，检验从可达状态出发的联合制动轨迹是否仍满足净距。 [A 模型 §4.3、§6.2](../A/A_model_proposal.md) · [合成反例](C_validation_plan.md#4-c-独立合成反例)

## 3. 两级方案

### 3.1 局部修复

1. 以故障资源、受影响任务以及与故障禁用区间、制动扫掠或停驻障碍相交的轨迹/资源预约为种子。扩张至同炉前后依赖、同浇次紧迫交接、共享工位/渡车、同车后续及相关邻车。因修复改变时窗或占用时，增补与新预约冲突的未锁定任务，直到影响闭包稳定或超出预算。
2. 固定 $t<\tau$ 的实际轨迹及事件日志。对跨越 $\tau$ 的动作截断历史部分，剩余段从同一 $x,v,\mathrm{load}$ 出发。冻结不可中断的动作和已发出的近期承诺。故障确实使承诺轨迹失效时，用安全停车或已授权的剩余动作替换未来段，记录原因及替换点。保持闭包外的可行预约原定时刻和分配。
3. 在闭包内更新就绪、占用和候选可达性。可平移未执行动作，在合法站点等待，插入预调位或调整未开始任务的车辆、次序。浇次和已锁定设备顺序仍约束。带载与已取任务只调整可中断运动或允许的放下时刻，遵守原持有者和物理接续。
4. 验收时回放完整五车后缀和所有资源及供钢交接；检查前缀、在途载荷、锁定预约无非法变化，所有硬条件达标，检查窗末端可安全续行。先尝试符合原计划约束的解。有安全迟到候选时保留为诊断，可执行性依据授权的放宽规则和实际回放确定。

### 3.2 滚动重优化

局部候选耗尽或预算将到、影响传播到多个节点/浇次、已锁预约阻塞受影响任务、同浇次余量转负或后续事件状态变化时升级。优先扩大可调整范围到下一关键供钢交接和相关空包清障。时间窗末端须可安全停驻或已有可验证的续行预约。窗口末尾尚未交付的带载包、外部资源、被占工位和未完成处理持续继承。临近的硬交接须在本窗验证，或有通过回放的窗外续行见证。仅有必要时间下界时，将该交接标为尚未验证并继续扩窗或等待状态更新。

在当前 $\tau$ 重新构建 A 的短窗时空弧模型。每车从快照节点出发，故障制动、停驻和不可中断的后缀弧固定。在途任务只生成考虑剩余距离、已完成装卸、持包和许可等待的弧。健康车用同一核验过的运动模板，未开始任务允许使用动态可达且合格的资源。每次只提交下一承诺段，提交前再核对最新快照的版本和完整回放。按下一已观测故障/恢复/占用释放或设定重算周期推进。求解限时可保留已验证的安全近端动作。若续排仍无候选且存在已验证的停车或等待动作，执行该短段并报告阻碍，遵守持包时限和轨道约束。若连停车或等待都无法验证，记录当前冲突或信息缺口，按现场应急流程处理。

## 4. 约束、目标与诊断

- **硬约束。** 安全净距、可达性、吊重、任务唯一分配/持有、工艺前序、资源容量、已执行前缀和已锁定设备/炉次顺序均须满足。每个钢包的持有转移仅发生在取放或授权交接事件。对工序故障区间，停机资源的服务能力为零，占用实体照常计入物理容量。无人可达、资源冲突、超温或最大持包时间违约均需定位到触发约束。
- **连续安全。** 在共同断点之间，若相邻行车恒加速，间距 $g(u)=g_0+\Delta v\,u+\Delta a\,u^2/2$，检查两端及落入段内的最小值驻点。故障车停驻段取 $v=a=0$，其他车所有运动与等待段均参加检查。$D_{kk'}$ 若按载荷改变，在每个适用区间及切换两侧检查。固定共轨顺序时，正净距保证不越车。授权旁路需用空间区段和进出占用重建冲突。 [A 模型 §4.3、§6.2](../A/A_model_proposal.md)
- **连续供钢。** 接收位可用且合法放下后，准备完成要求 $B_{i,\mathrm{CC}}\ge a_{h(i)}+b_i$。在供钢口径确定后，对相邻同浇次要求 $G_i^{\min}\le B_{i',\mathrm{CC}}-F_{i,\mathrm{CC}}\le G_i^{\max}$。$B,F$ 使用实际供钢事件，或在仿真中由可核的历时、在制状态和供钢缓冲演化确定。限制 $F$ 的工艺有效范围并检查炉内供钢，避免自由延长前炉结束掩盖断供。初态已供钢的炉次用已知余量推导交接上界，换中包和重启用授权工艺另建。缺缓冲证据时只报告座包风险。工艺硬截止与可协商生产计划的时点单独存放。 [A 模型 §4.2](../A/A_model_proposal.md)
- **目标。** 严格模型先满足原计划固定窗及连续供钢。在获得放宽授权后的恢复模型中，可按字典序最小化明确允许的中断浇次数、受影响炉次和未交任务数，再最小化最大和总计划延误。其后按 A 的口径最小化钢包等待和有载/空驶车秒，最后压缩改派数与起吊时刻的绝对偏移。缺交只有在允许的调度边界内引入并受前序连锁约束；对比时保留所有目标项。断浇恢复只能在真实可重启的工艺情景中建模。已锁窗口若需要在方案间比较改派代价，可在同等服务与延误水平下给出等待、车时与改派的取舍。

| 结果 | 判定与证据 |
| --- | --- |
| **原计划仍可维持** | 给出通过全轨迹、资源和供钢回放的见证，满足原计划锁定顺序及交付承诺。记录未来预约是否经调整。 |
| **必须接受延误** | 先用可复查的证据否定原计划承诺的可行性，再给出按授权放宽计划目标后仍满足安全和工艺边界的见证。报实际延误和已证下界，两者相等时可报最小延误。 |
| **存在物理不可行证据** | 在声明的拓扑、许可、状态、时域与硬边界下，对强制任务给出资格空集、占轨可达域、资源容量证书或乐观时限下界。若仅证明原计划时限失守且延误可被授权，仍须单报恢复层的求解状态。 |
| **算法未找到解** | 无物理证书时，记录启发式候选耗尽、离散网格无解、限时或输入缺口及检查范围。离散 MILP 的证书只覆盖生成的弧及网格；安全候选迟到可报告观察到的服务损失，不能判定必然迟到。 |

最早可放下界可由经核的最早物理就绪、所有合法车辆和路径中的最快必要移动、必需装卸、已在途余段及不可绕过的阻挡解除下界构造。可省略等待与竞争以放松问题，同一阶段可并行时用最大值，避免重复加和。在未知恢复区间中判断必然迟到，要允许最乐观的可能恢复时点。若乐观到位下界仍晚于物理供钢截止，即可证明相应交接受影响。待核资格和未知旁路会限制证书范围。 [C 验证反例](C_validation_plan.md#4-c-独立合成反例)
