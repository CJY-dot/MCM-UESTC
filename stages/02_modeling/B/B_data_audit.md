## 2. 字段与对账

- **计划时点。** 计划表的「浇铸开始时间」「浇铸结束时间」用于连铸窗口。「连铸开始时间」和「连铸结束时间」列全空。精炼编号的时间槽含义随路线和字段而变，先保留为有来源的计划槽位。具体时段和实际处理历时的对应关系留待核实。
- **实际时点。** 精炼处理始末、RH 进出处理位、脱气始末、起吊、位置到达、座包和开浇分别入表。重复表头用列位和名称区分，时长字段与日历时点维持不同类型。时点转成统一的本地日期时间轴，历时用秒，毛重按原表吨位口径保存。无法恢复日期的值保留原文和解析状态。
- **身份匹配。** 先以熔炼号取候选，再用设备、出钢记号、钢包号、临时罐号或连铸浇次核对。单一兼容记录可用。重复候选只有出现足够的辅助证据时才择一。无匹配、标签冲突和多义候选均有状态，后续统计只取对应字段可用的子集。
- **现场设备。** 附件有 1#LF 和 3#LF，没有 2#LF 工作簿。现场设备数、站点命名和源系统标签的对应关系需要核对。当前保留源标签。未经过某精炼工序造成的正常空值与所需设备缺失分开判读。

## 3. 已生成的事件与任务接口

| 本机文件 | 粒度与用途 |
| --- | --- |
| `audit.json` | 各工作簿 SHA-256、表头和列级类型、缺失、重复、解析结果、按组的清洗统计 |
| `events.csv` | 炉次 × 事件 × 原始来源。区分计划和实际，含文件、工作表、原行列、解析、匹配和可信度状态 |
| `tasks.csv` | 按计划路线展开的重包、空包及边界腿。含前序、起讫、毛重证据、起吊代理、计划截止代理与行车资格列 |
| `calibration.csv` | 经对应事件筛选的正历时、有符号偏差及来源。可核对同义计划时长时保留该字段 |

事件侧保留 **58,049 条观测行**，其中 39,693 条选为规范事件，9,854 条为同义一致的佐证记录，258 条同义事件时间或站点冲突，8,244 条为保留的候选或未解析记录。有冲突的事件保留源证据，暂不进入该事件的规范时点。校准表共 **8,868 个样本**，包含不同用途的历时和偏差。同一炉次可贡献多种指标。

任务侧共 **9,040 条候选腿**，其中 5,242 条进入 EF 跨候选，3,798 条保留为外部资源接口。生成的路径覆盖转炉至精炼、炉间精炼、精炼至连铸及空包翻渣、渡车、热修和返回。返回细段按边界接口保留，未观测的动作时间和资源容量待补。每条前序连接同一炉次，并验证了前序端点与后继起点一致。

## 4. 调度前的资格核对

- 任务表有 6,076 条至少一个站点未知，5,083 条毛重未知，1,682 条带歧义或来源冲突标记。450 条记录的起吊早于所选前序处理结束，20 条的到达早于起吊。这些标记可重叠，任务数用于覆盖审计。
- 5,204 条候选任务带历史起吊代理，其中 470 条带前述两种时序异常之一。验证器应先按 `flags` 和来源查明冲突，再确定求解输入。字段 `physical_release_s`、正式窗口与 `eligible_cranes` 留待补全。`cranes_by_capacity` 仅是吨位筛选，计划开浇代理还要按座包提前量转成窗口。
- 从「重罐吊起」回减一项钢车时长可得 768 条候选，其中 90 条缺出钢结束作比较，余下 678 条里有 626 条得到早于出钢结束的到位时刻，仅 52 条满足该前后关系。这个字段暂不用于自动还原物理可吊时刻。前序完成与历史起吊分别作为待核验的时间下界和保守代理。
- 翻渣开始可作空包到站的上界代理，无法据此精确还原放下时刻。热修、平车和跨区资源容量需由设备信息确认。实际吊起至座包合并了运输与其他作业，不适合单独反推速度、加速度和距离。

下一阶段先在手工复核过的短窗上填写可吊时刻、合法收包窗口、占用及站点可达性，再将任务交给派车程序。对账、运行方式和复现路径见 [B 交接](B_HANDOFF.md)。
