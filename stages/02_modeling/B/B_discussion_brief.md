# B 成员讨论简报

建议统一采用**事件链驱动的派车与独立连续轨迹校验**。先冻结少量已核任务的时窗、可达图和行车初态，再比较允许保守预调位的基线与余量优先派车。对困难短窗，用原短验证的枚举思路或限时 MILP 对照。现有原型选择单个共享运动预约，便于核对轨迹和诊断下界。

## 已验证的结果

- 已审计 12 个工作簿，建立来源可追溯的事件与候选运输接口。1,266 份有效计划中 1,051 份选定一条兼容主表记录。时序冲突、未知站位、毛重和设备空缺需在派车前逐项筛查。
- 场景二的共同样本对照以真实 LF 历时训练池提供扰动形状，按日留出。用独立抽样与同日相邻记录成对抽样比较依赖假设，固定种子，并对两策略使用同一扰动。在历史四任务窗，先到先服务与余量规则未测得优势。合成竞争窗中，两规则做出不同的首次决策，均有 3 项按时到位。
- 场景三的就绪延迟注入保留了首项已承诺动作。长时注入下，原型仍能安全输运四项，按时完成从 3 项降到 2 项。后续要进一步验证同浇次在接收位与其他炉次同时占用时的恢复方案。

## 共同决策

| 负责人 | 需要确认 |
| --- | --- |
| A | 统一 `physical_release_s` 和可见信息的定义。共轨排程中加入能预调位的可行基线，分开统计候选阶段迟到诊断和硬窗口验收。冻结五车轨迹接口、跨窗初态与相邻净距。 |
| B | 继续确定 LF/RH 的计划槽位语义、设备标签与实际站位的映射。优先在可手工审计的较长窗口确认接收位和前序冲突，再扩充数据。 |
| C | 核查换位时的轨迹区间内部净距、随机抽样的信息边界和全目标任务分母。比较同炉残差向量与时间块，审查跨时间留出和故障报告是否夸大。 |

模型可回答相对窗口、条件可行性和策略对照。归一化轨道、速度档、特殊区域、故障率和修复历时目前依赖确认或明示情景。详见 [模型方案](B_model_proposal.md) 和 [参数摘要](B_parameter_summary.md)。
