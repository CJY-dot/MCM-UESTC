## 2. 逐任务等待与截尾

对每个已知起点 $a$，终点 $b$ 在 $H$ 内出现则记完整等待 $b-a$，终点缺失且阶段已开始则记右截尾下界 $H-a$。缺起算依据保留空值。不适用阶段单列。起点和终点均为模型事件。

- **条件释放到来源位准入。** 根任务使用 `physical_release → source_entry`。B 已确认缺独立现场来源位到达事件，这一段是模型准入延迟。
- **来源位就绪到起吊。** 根任务用 `source_entry → pickup_start`。非根任务在前序放下和持有资源能对账时，用同源位上的条件就绪时点至起吊。已纳入前序工序或准备的时间保持在原阶段。
- **有载停顿。** 从 `pickup_complete → delivery_arrival` 的轨迹内查实际静止，保留运动及可辨认的停顿类型。另列 `delivery_arrival → drop_start`。空载待避和正常带载移动分别作为行车时间，起落操作与后两段等待分开。
- **落包到绑定工序开始。** 以 `drop_complete` 对接精炼、供钢或翻渣开始。窗末仍无开工的待时右截尾，其中 W01 主条件 11 项，已落包但未完工的 11 项均处于这个阶段。

## 4. 同浇次供钢风险代理

## 5. 候选诊断与配对解释

同窗、同条件和重复号内去掉策略标签后归并完全相同的执行。复算得到 **25,407 个成功派车决策**，各只有 1 项可派任务。每任务有 1/2/3 台可行车辆的决策分别为 4,418/10,579/10,410，共 **56,806 个任务—车辆选项**。两窗主条件按同口径分别有 2,113/2,088 个成功派车决策。

沿用 C 的只读必要条件筛查，由归档可见事件、车辆待避和停车结束点、成功决策时间构造 193,824 个不同的可观察检查点。其中 168,417 个检查点未记录派车。必要筛查后剩 0/1/2 项任务的检查点为 165,029/28,789/6。剩余项仍要通过轨迹与预约检查。检查点按时刻去重，无法还原同刻的逐轮内部队列，实际全量候选生成轮数和其中零可行数仍未知。已归档的 C 返修探针在 38 个指定 FCFS 重复中记录 1,267 个候选轮，其中 1,123 轮确实零候选，只用于该子集。

可观察必要筛查分别报告成功时刻与未记录派车时刻的首个排除原因。全量未派车检查点中，前序未完成 1,261,227、输入阻塞 673,668、释放不可见 341,106、来源持有者不可用 74,565、目的占用或预约 37,793、起吊窗已过 75,134，单位为任务×检查点。路径和资格按其输入阻塞或可观察筛查层处理。同一任务可在不同时间重复被排除，合计不是任务丢失数。共轨/停车在候选轨迹生成后方可判断，完整拒绝日志不在全量归档，不能反推从未生成的路径在物理上不存在。 [C 静态筛查代码](../C/q2_event_audit.py)

24 个条件中三策略在每个重复的完整轨迹和派车相同。公开汇总仍分别留三策略的任务、等待、车辆和供钢代理指标。配对差按相同窗、条件和重复号计算，置信区间以每重复一个差值作单位。配对指标包含等待状态计数和已知/截尾下界合计，此类差值只涉及可观察的量。逐任务 P50/P90 不将任务项次当作独立推断样本。所有已报配对项在本归档为零，说明优先规则在当前候选集合中未获得可改变的任务选择。结果不能外推为规则效益等价。
