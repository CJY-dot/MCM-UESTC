## 每轮交付与权限

**Q1、Q2、Q3 各自严格执行 B → A → C → 验收。** B 的 PR 合并后才启动本轮 A。A 的 PR 合并后才启动本轮 C。C 的独立验收通过并归档后，由项目负责人启动下一轮。上一轮处于返修、证据待补或条件未达标时，下一轮保持未开始。

| 负责人 | 输入与启动条件 | 交付 | 本环节核对 |
| --- | --- | --- | --- |
| B 数据 | 已过审的范围、契约及本轮基线。授权计划、日志、三处身份规范及历史审计 | 标准化事件、需求任务、设备准入、EF 工位和快照，有据的外部交接、数据审计、参数证据表及交接 | 单位与来源可追溯，派车和占轨状态分开，前序、可吊和窗口语义明确，A/B/C 分级与覆盖可解释。未知字段保持未知 |
| A 调度 | B 的交付已合并到 `main`，以对应提交及输入版本为准 | 本轮共用 EF 调度接口的实现、派车安排、轨迹、运行记录、指标与失败范围 | 按 B 的接口消费输入，保留条件与阻塞，输出足够的重放字段。求解候选和正式可行结论分别标记 |
| C 验证 | A 的交付已合并到 `main`，使用与 A 相同的规范输入及轨迹 | 独立检查器、本轮验收及证据记录、违规位置和返修单 | 从输入、事件和轨迹独立重算。覆盖正确性、约束、范围及失败解释；提交违反项的对象、时刻/区间、阈值或必要前序 |

B 负责数据接入与更正审计，保留原始文件和已有批准映射。A 复用 B 的数据模块，统一接口的变化交负责人裁决。C 自行检查可行性，使用 A 的候选轨迹与公开接口作输入。A 开发时的自测供定位，独立验收在 C 环节闭环。

## Q1、Q2、Q3 的推进与门槛

| 轮次 | B 输入合并 | A 方案合并 | C 独立验收及进入下一轮的条件 |
| --- | --- | --- | --- |
| Q1 确定性 | 确定性需求任务、EF 初态和占轨、工位证据、硬/计划窗口、交接条件、范围与 A/B/C 准入 | FCFS 与最紧交付余量使用同一候选机制；输出空驶、取放、等待和合法待避预约。困难短窗可用有限 EF 时空弧作诊断 | 核对身份、前序、容量、唯一持有、范围、外部交接、匀速段全时域净距和失败标签。复用现有短窗及停轨反例。计划硬界和安全约束按批准范围验收后才进 Q2 |
| Q2 随机与动力学 | 在 Q1 接口上补同义历时、时间偏差、训练与留出、速度档、加减速及参数依据，记录外部交接扰动的证据 | 以相同信息和扰动比较策略，扰动沿事件图传播，输出带速度和加速度的 EF 轨迹及配对指标 | 复核时间分割、同样本与信息可见性、动力学连续、限速与内部最小净距。复用内部净距反例，按共同分母披露未完成项后才进 Q3 |
| Q3 故障与恢复 | 记录工序、EF 停机及外部交接中断的证据和许可，区分实际发生、获知、恢复公告及状态 | 从实际快照局部修复，再在 EF 内滚动重优化。输出冻结前缀、制动停驻、持有继承、改动量和可行/失败范围 | 复核制动、占轨、前缀、载荷和恢复信息权限，复用停轨和运动带载反例。区分严格可行、证实需延误、物理不可行与未判定，完成最终验收 |

每轮冻结任务范围、输入版本和验收口径。缺少必要证据时给出条件边界或输入阻塞，清楚报告覆盖。安全、工艺或交接的关键阻塞未解决时，负责人须先明确可验收范围或安排补证；仅通过旧回归不能作为现场验收通过的依据。

## 待核实与阻塞条件

| 待核实 | 负责人 | 阻塞条件 |
| --- | --- | --- |
| EF 工位具体取放点、段长、准停位、安全距离、每车初态与两台 150 t 的占轨 | B 收集与登记，A 说明求解影响，C 在本轮输出后验收 | 影响路径或安全而缺证据时，相应窗口无法正式验收 |
| 倒渣位与 EF 位置、渡车接驳、接车容量、释放及返程归属 | B 对账，负责人确认未决边界 | 该接点的就绪、持有或安全无法闭合时，对应运段保留待核或条件范围 |
| 可吊、座包与真实供钢硬界 | B 核对记录，负责人确认工艺语义，C 核验 | 无证据的硬界不作正式验收条件。真实供钢结论缺依据时只报风险代理 |
| Q2 动力学与统计依据、Q3 故障状态和恢复许可 | B 按轮补材料，A 使用可见信息，C 独立核验 | 缺关键参数时仅可在有依据的条件配置验收；缺硬安全或恢复前提须退回补证 |

## PR 与返修

每个环节从上一交接已合并的 `main` 开独立分支，只改该负责人获授权的目录和模块。PR 写明基线 SHA、对应输入或输出版本、改动范围、验证和待核项，原始工作簿与生产明细留本机。B、A 分别通过合并交接。C 在自己的目录记录独立验收，项目负责人确认结果并归档后放行下一轮。发现缺陷时由原负责人修复，合并后 C 使用更新基线重新验收。接口变更由负责人明确批准，其他成员的原始交付保留。

Stage 02.5 审查期间，以上开发、实验与逐轮启动均未开始。开发任务由项目负责人在对应交接通过后发出。
